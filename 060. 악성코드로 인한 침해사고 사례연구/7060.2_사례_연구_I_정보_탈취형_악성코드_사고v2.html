01. 인포스틸러의 정의와 위협 지형의 진화

InfoStealer(인포스틸러; 정보 탈취형 악성코드)는 시스템에 침투하여 자격 증명, 금융 정보, 브라우저 세션 등을 무단 수집하고 공격자의 C2(Command and Control; 명령 및 제어) 서버로 전송하는 특수 멀웨어입니다.

현대의 인포스틸러는 단순한 비밀번호 탈취를 넘어, MFA(Multi-Factor Authentication; 다중 인증)를 무력화하기 위한 Session Hijacking(세션 가로채기) 기법으로 고도화되었습니다.

"공격자는 ID와 PW를 알 필요조차 없습니다. 활성화된 유효 쿠키(Cookie)를 탈취하는 것만으로 AWS, Azure와 같은 클라우드 관리 콘솔에 즉각적인 권한 획득이 가능하기 때문입니다."

MFA (Multi-Factor Authentication, 다중 인증) 지식(비밀번호), 소지(OTP), 존재(생체정보) 중 두 가지 이상의 요소를 결합하여 보안을 강화하는 인증 체계입니다.
Session Hijacking (세션 가로채기) 로그인이 완료된 사용자의 유효한 '세션 토큰'이나 '쿠키'를 탈취하여, 추가 인증 절차 없이 시스템에 접속하는 공격 기법입니다.

02. 핵심 공격 매커니즘 Technical Pipeline

초기 침투
Initial Access

SEO 포이즈닝을 통해 검색 상단에 가짜 유틸리티를 배포하여 사용자 다운로드 유도

Phishing Attack

지속성 및 우회
Persistence

안티-분석 기법으로 샌드박스 감지 시 중단하고, 탐지 우회를 위한 시스템 상주 시도

Anti-Analysis

데이터 수집
Collection

브라우저 SQLite DB 파싱, SSH 키, 클라우드 자격 증명 및 암호화 화폐 지갑 검색

Data Harvesting

데이터 유출
Exfiltration

수집된 데이터를 압축 및 암호화하여 HTTPS / Telegram Bot을 통해 C2 서버 전송

C2 Transmission
SEO 포이즈닝 (Search Engine Optimization Poisoning) 검색 결과 상단에 악성 사이트를 노출시켜 사용자의 접속을 유도하는 신뢰 기반 기격 기법입니다.
C2 서버 (Command and Control Server) 해커가 감염된 컴퓨터에 명령을 하달하고 데이터를 수집하기 위해 운영하는 원격 제어 인프라입니다.
니모닉 (Mnemonic) 암호화 화폐 지갑 복구용 단어 조합으로, 유출 시 지갑의 전권을 상실하게 되는 핵심 탈취 목표입니다.

인포스틸러의 주요 타겟 및 2차 피해 시나리오

Cloud Infrastructure (AWS/Azure)

개발자 환경의 .aws/credentials 파일 유출은 단순 사고가 아닌 인프라 전면 상실을 의미합니다. 공격자는 탈취한 권한으로 고사양 인스턴스를 생성하여 암호화 화폐를 채굴하거나(Cryptojacking), 기업의 핵심 DB를 통째로 덤프하여 다크웹에 유출합니다.

Enterprise SaaS (Slack/Jira/Notion)

사내 협업 툴의 세션 쿠키가 탈취될 경우, 추가 인증 없이 공격자가 정당한 팀원으로 위장하여 내부 기밀 대화와 프로젝트 산출물을 실시간으로 열람합니다. 이는 보안 관제 시스템에서 탐지하기 매우 난해한 유형의 위협입니다.

Case Study: XYZ 기업 정보 유출 사고 심층 분석

01
초기 침투 (Spear Phishing)

직원을 타겟으로 한 Spear Phishing(스피어 피싱; 표적형 피싱) 이메일을 통해 매크로가 포함된 문서 배포 및 실행 유도

02
인증 키 탈취 (Credential Harvesting)

브라우저 내 VPN 자격 증명과 로컬 환경 변수의 API Key를 자동 수집하여 유출

03
내부 확산 (Lateral Movement)

탈취한 키를 이용해 정당한 관리자 권한으로 클라우드에 접속, 기밀 프로젝트 정보 대량 유출

04. 전문가적 방어 전략 Defense in Depth

인증 및 세션 하드닝

  • 하드웨어 보안 키 (FIDO2): YubiKey와 같은 물리 보안 키를 필수화하여 단순 쿠키 탈취로는 로그인이 불가능하게 설계합니다.
  • 적응형 세션 제어: 모든 토큰에 짧은 TTL을 적용하고, 비정상적 IP나 환경 감지 시 즉시 Revoke(세션 무효화) 처리합니다.

엔드포인트 및 가시성 강화

  • EDR/XDR 도입: 행위 기반 모니터링을 통해 시그니처가 없는 인포스틸러의 동작을 실시간 탐지 및 차단합니다.
  • 브라우저 보안 정책: GPO를 통해 브라우저 내 비밀번호 저장 기능을 금지하고 엔터프라이즈 패스워드 매니저 사용을 강제합니다.

05. 공급망 공격 (Supply Chain Attack) 분석

Supply Chain Attack(공급망 공격)은 신뢰할 수 있는 소프트웨어 벤더의 인프라를 먼저 장악한 뒤, 정식 업데이트 채널을 통해 다수의 고객사에게 악성코드를 유포하는 고도의 전략적 공격입니다.

이는 타겟이 신뢰하고 사용하는 '공급망' 자체를 무기화하기 때문에 Transitive Trust(신뢰의 전이)를 악용한 가장 방어하기 어려운 위협으로 꼽힙니다.

SolarWinds Orion Incident Case

공격자는 SolarWinds사의 빌드 서버에 직접 침투하여 Orion 업데이트 패키지에 SUNBURST 백도어를 주입했습니다.

공식 디지털 서명을 포함한 이 업데이트는 수천 개의 정부 부처와 기업에 설치되었으며, 공격자는 이를 통해 장기간 탐지 없이 원격 제어 및 기밀 유출을 수행했습니다.

Core Insights
  • SBOM(Software Bill of Materials) 도입을 통한 가시성 확보 절실
  • 빌드 서버 및 파이프라인 무결성 검증 체계 고도화 필요
  • 서드파티 벤더의 보안 수준에 대한 지속적 보안 감사 수행
